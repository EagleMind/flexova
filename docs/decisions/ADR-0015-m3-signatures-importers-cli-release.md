# ADR-0015: M3 decisions (signature format, importers, CLI, releases)

- **Status:** Accepted, 2026-11-02.
- **Refines** ADR-0011 with the exact signature format.
- **Supersedes** ADR-0011's "ECDSA P-256 fallback": every engine Flexova targets now has Ed25519 in WebCrypto.

## Decisions

| #   | Decision                                                                                                                                                                                                                                                                                                                                            | Why                                                                                                                                                                                                                                                                            |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | **Signatures are a JWS Compact Serialization with a detached payload, over the exact bytes of `META-INF/flexova.json`.** One signature per package. The rules are in `spec/signature.json`, with six verification codes checked in a fixed order.                                                                                                   | Compact detached JWS is supported by every JOSE library, and it's one line of ASCII. The manifest schema requires a complete `entries` list, so signing the manifest covers every byte of content. That made a separate "uncovered" code unnecessary, and it was removed.      |
| 2   | **Signers emit `alg: "Ed25519"` (RFC 9864). Verifiers also accept the older `EdDSA`.** The header must not carry `jwk`, `jku`, `x5u`, `x5c`, `crit` or `b64`.                                                                                                                                                                                       | RFC 9864 deprecates the polymorphic `EdDSA`. Keys are only ever taken from the verifier's trusted set, which closes the "embedded key" and unencoded-payload attack classes.                                                                                                   |
| 3   | **Verification fails on non-canonical encodings and on an `S` that is not below the group order,** as OpenSSL does. The Python implementation is pure RFC 8032.                                                                                                                                                                                     | The two implementations agree on malleated signatures. The conformance suite has a fixture for this.                                                                                                                                                                           |
| 4   | **TypeScript uses WebCrypto Ed25519; Python uses a pure-Python RFC 8032 implementation.** Both sign and verify, and both produce byte-identical signature files.                                                                                                                                                                                    | There are no new dependencies on either side. The Python code is not constant-time. That's fine for verifying, and for signing in build pipelines. Keys of high value belong in an HSM or a hardened library.                                                                  |
| 5   | **The Markdown importer maps the mdast syntax tree (micromark with GFM) straight onto the profile,** rather than going through a remark→rehype pipeline.                                                                                                                                                                                            | Direct mapping gives full control over ids, figures, callouts and notes, and the result is valid by construction. The parser is small, ESM-only and runs in browsers, so FlexPad (M5) can import offline.                                                                      |
| 6   | **The Pandoc importer reads Pandoc's JSON syntax tree** (`pandoc -t json`, API 1.22 or later), not its HTML output.                                                                                                                                                                                                                                 | A typed tree needs no HTML parser. One mapper then covers DOCX, ODT, HTML, LaTeX, reStructuredText and everything else Pandoc reads.                                                                                                                                           |
| 7   | **Authoring conventions:** GitHub alerts (`> [!WARNING]`) and Word paragraph styles named Note, Tip, Important, Warning and Caution become callouts with a visible label. Footnotes become per-chapter endnotes linked both ways. Chapters split at level-1 headings and at file boundaries. Ids are ASCII, and GitHub-style anchors still resolve. | These conventions already exist in tools people use. The label makes a callout's meaning visible without color, and readable by screen readers.                                                                                                                                |
| 8   | **Importers never drop content silently.** Raw HTML, remote images, links to outside files and TeX math are simplified, and each is reported as a warning. `flexova build --strict` turns warnings into failure.                                                                                                                                    | Authors need to know what changed. CI can insist on a clean conversion.                                                                                                                                                                                                        |
| 9   | **CLI builds are reproducible:** a missing identifier becomes a UUIDv8 derived from the input, and the modification time comes from `--modified`, the project config, or `SOURCE_DATE_EPOCH`.                                                                                                                                                       | This matches the core writer's deterministic output (ADR-0008), and lets CI compare builds.                                                                                                                                                                                    |
| 10  | **Releases:** Changesets versions the packages, and `scripts/publish.mjs` publishes them with `pnpm pack` and then `npm publish`, using trusted publishing (OIDC) with provenance. PyPI uses trusted publishing too. The Docker image goes to GHCR.                                                                                                 | `pnpm pack` rewrites `workspace:*` dependencies, and npm 11.5.1+ handles OIDC natively. That avoids relying on unconfirmed OIDC support in `changeset publish`. GHCR needs no extra account.                                                                                   |
| 11  | **The very first npm publish of each package is manual** (owner action).                                                                                                                                                                                                                                                                            | npm, unlike PyPI, can't configure trusted publishing for a package that doesn't exist yet.                                                                                                                                                                                     |
| 12  | **The CLI always runs Pandoc with `--sandbox`, and extracts media only for container formats** (DOCX, ODT, EPUB, notebooks). The importer embeds an image only if it sits inside the source's folder or the extracted media.                                                                                                                        | Without the sandbox, Pandoc fetches every image an HTML source references, including local files and URLs. Converting an untrusted document could then embed private files, or make network requests on a server. A CLI test covers escaping, absolute and remote image paths. |

## Evidence

- **Signature fixtures:** all 24 give the expected code in both TypeScript and Python. The generator's stdlib signer is checked against RFC 8032 TEST 1, and Python passes TESTs 1–3.
- **Importers:** the sample Markdown manual and the DOCX sample convert with no warnings, validate with no issues, and Ace reports 0 violations. epubcheck runs in CI.
- **Release dry run:** `changeset version` takes every package to 0.1.0. The packed tarballs carry real dependency versions. A clean install of the packed CLI (67 packages, 6.6 MB) builds and checks documents.

## Consequences

- **Math:** TeX math in Pandoc input stays TeX (shown as code) until a TeX→MathML step is added.
- **Docker:** the image can't be built in the development container, which has no Docker daemon. CI builds it on every push and converts a DOCX with it.
